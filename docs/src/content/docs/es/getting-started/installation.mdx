Pyzed necesita **Python 3.10 o superior**.

## Desde PyPI

<Tabs syncKey="pkg">
	<TabItem label="uv">
		```bash
		uv add pyzed-ui          # en un proyecto de uv
		uv run python main.py
		```

		Para empezar una app nueva como proyecto de uv, ve a [Crear un proyecto](/pyzed/es/getting-started/new-project/).
	</TabItem>
	<TabItem label="pip">
		```bash
		pip install pyzed-ui
		```
	</TabItem>
</Tabs>

El paquete se llama `pyzed-ui` en PyPI (el nombre `pyzed` ya estaba ocupado), pero se importa como `pyzed`.
Los wheels precompilados para Linux, macOS y Windows incluyen el motor de Rust, así que no
necesitas compilar nada.

<Aside type="caution" title="Antes de la primera versión en PyPI">
Si `pip install pyzed-ui` no encuentra un wheel para tu plataforma, instala desde el código fuente
(abajo). Necesitarás Rust estable.
</Aside>

## Desde el código fuente

```bash
uv add git+https://github.com/albakore/pyzed        # uv
pip install git+https://github.com/albakore/pyzed   # pip
```

Esto compila la extensión de Rust, así que necesitas [Rust estable](https://rustup.rs) y las
dependencias de sistema de tu plataforma:

<Tabs syncKey="os">
	<TabItem label="Linux">
		```bash
		# Debian / Ubuntu
		sudo apt install build-essential libxkbcommon-x11-0
		curl https://sh.rustup.rs -sSf | sh
		```
	</TabItem>
	<TabItem label="macOS">
		```bash
		xcode-select --install
		curl https://sh.rustup.rs -sSf | sh
		```
	</TabItem>
	<TabItem label="Windows">
		Instala [Rust con rustup](https://rustup.rs) y las *Build Tools for Visual Studio*
		(carga de trabajo "Desarrollo para el escritorio con C++").
	</TabItem>
</Tabs>

## Desarrollar Pyzed

Para trabajar en Pyzed, clona el repositorio. Necesitas [Rust estable](https://rustup.rs) y las
dependencias del sistema de arriba.

<Tabs syncKey="pkg">
	<TabItem label="uv">
		```bash
		git clone https://github.com/albakore/pyzed && cd pyzed
		uv sync                          # crea .venv, compila el núcleo de Rust (release) e instala pyzed editable
		uv run pytest tests
		uv run python examples/gallery.py
		```

		- `uv sync` también instala el grupo `test` (maturin y pytest). La primera compilación tarda unos minutos.
		- Los cambios en Python (`python/pyzed/`) se usan directamente.
		- Después de cambiar código de Rust (`src/`), el siguiente `uv run` o `uv sync` recompila el núcleo solo.
		- `uv sync --extra designer` añade ty y ruff para el editor de código del diseñador.
	</TabItem>
	<TabItem label="pip">
		```bash
		git clone https://github.com/albakore/pyzed && cd pyzed
		python -m venv .venv && source .venv/bin/activate
		pip install maturin pytest
		maturin develop --release        # repítelo después de cambiar código de Rust
		pytest tests
		python examples/gallery.py
		```

		Usa `--release`: la build de depuración es mucho más lenta al usar la ventana.
	</TabItem>
</Tabs>

## Linux y WSL

Pyzed ajusta algunas cosas antes de abrir la primera ventana:

- **Silencia los avisos del driver de la GPU.** Mesa imprime mensajes como `libEGL warning:
  failed to get driver name for fd -1` o `MESA: error: ZINK: failed to choose pdev` mientras el
  renderer busca un backend que funcione. No afectan a nada, así que Pyzed define
  `EGL_LOG_LEVEL=fatal` y `MESA_LOG=null`. Con `PYZED_GPU_LOGS=1` vuelven a aparecer.
- **En WSL usa X11.** El compositor Wayland de WSLg corta la conexión al maximizar o
  redimensionar una ventana, y eso imprime `Io error: Broken pipe (os error 32)`. En WSL, Pyzed
  usa X11 (a través de XWayland). Con `PYZED_WAYLAND=1` se mantiene Wayland.

Las variables que definas tú (`EGL_LOG_LEVEL`, `MESA_LOG`, `WAYLAND_DISPLAY`...) nunca se tocan.
