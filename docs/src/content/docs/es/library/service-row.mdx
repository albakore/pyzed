:::tip[En pocas palabras]
Una línea de una página de ajustes para una herramienta que usa el asistente: si funciona, un interruptor para encenderla o apagarla y un menú con más opciones.
:::

`ui.ServiceRow` es un componente para algo que usa un agente de IA (un servidor MCP, un agente externo, una skill) en una página de ajustes: un icono, el nombre con su versión (`version`) y un punto de estado, el `detail` (su comando o URL, en letra monoespaciada) y un `summary`; luego un spinner mientras está `busy`, un botón principal (`primary`, como Actualizar o Instalar), un interruptor (`enabled`; `None` lo oculta) y un menú `⋯` con las acciones (`actions`, de `ui.MenuItem`). `status` colorea el punto: `running` e `installed` en verde, `starting` en amarillo, `update` en el color de acento, `error` en rojo, `off` y `missing` en gris. `status_text` es el tooltip del punto, y se ve bajo el nombre con `error`, `missing` y `update`.

## Cuándo usarlo

- En los ajustes de una app con agentes de IA: una fila por servidor MCP, agente o skill.
- Para cualquier lista de servicios que se pueden encender y apagar, actualizar o quitar.

## Uso

```python
import pyzed as pz
from pyzed import ui

class Settings(pz.App):
    def __init__(self):
        self.on = True

    def view(self):
        return ui.ServiceRow(name="github", detail="npx -y @modelcontextprotocol/server-github",
                             status="running" if self.on else "off", enabled=self.on,
                             on_toggle=lambda e: setattr(self, "on", e.value),
                             actions=[ui.MenuItem("Remove", self.remove, icon="trash-2", danger=True)])
```

## Eventos

Fila de servicio tiene **2 eventos propios**, en la tabla de abajo. Como todo widget, también tiene los **18 eventos comunes** (`click`, `double_click`, `right_click`, `mouse_enter`, `drag`, `key_down`, `resize`…), que se conectan con `.on(...)`: mira [Eventos](/pyzed/es/guides/events/) y [Eventos de cada componente](/pyzed/es/library/events/).

Es un `pz.Component`, así que también lanza `on_mount` y `on_unmount`, y sus handlers reciben un `pz.Event` cuyo `value` trae el dato.

| Evento | El handler recibe | Cuándo |
| --- | --- | --- |
| `on_toggle` | `(event)` | Se cambió el interruptor. |
| `on_primary` | `(event)` | Se pulsó el botón principal. |

**El handler recibe** es lo que Pyzed le pasa a tu función: `()` es nada. Cualquier handler también puede ser un mensaje (un valor que no se puede llamar), que va a `update()`.

### Manejar los eventos

Los mismos eventos escritos de tres formas. **Imperativa**: métodos de la app que cambian `self`. **Declarativa**: los handlers producen mensajes y un único `update()` decide. **Funcional**: una función pura dibuja un estado inmutable y pide cambios con `set_state(...)`. Mira [Imperativo, declarativo y funcional](/pyzed/es/guides/code-styles/).

class Settings(pz.App):
    def __init__(self):
        self.on = True
        self.updates = 0

    def view(self):
        return ui.ServiceRow(name="github", status="running" if self.on else "off", enabled=self.on,
                             primary="Update",
                             on_toggle=lambda e: setattr(self, "on", e.value),     # the switch
                             on_primary=lambda e: setattr(self, "updates", self.updates + 1))
```

from dataclasses import dataclass


@dataclass
class Enable:
    on: bool


class Settings(pz.App):
    on = True

    def update(self, message):
        match message:
            case Enable(on):
                self.on = on

    def view(self):
        return ui.ServiceRow(name="github", enabled=self.on, status="running" if self.on else "off",
                             on_toggle=lambda e: Enable(e.value))
```
