:::tip[En pocas palabras]
Una cosa que hizo un asistente de IA, como leer o cambiar un archivo. Púlsala para ver los detalles; si necesita tu permiso, pregunta con botones de Permitir y Rechazar.
:::

`ui.ToolCall` es un componente para una acción de un agente de IA (leer un archivo, editarlo, ejecutar un comando), dibujado como en Zed: una línea con el estado, el título (`title`) y sobre qué trabaja (`detail`), y un clic despliega la entrada (`input`) y la salida (`output`), más las imágenes (`images`) si las hay. Las ediciones, los comandos (`kind` `edit`, `delete`, `move` o `execute`) y las llamadas que esperan son tarjetas. `diffs` muestra los cambios que hizo como diferencias de colores y, mientras se ejecuta, `progress` muestra las últimas líneas que imprimió un comando. Mientras `status` es `"waiting"` pregunta en la misma tarjeta: Permitir siempre, Permitir o Rechazar, que llegan a `on_allow`, `on_allow_always` y `on_deny`. El componente recuerda si está desplegado; tu app solo guarda los datos.

## Cuándo usarlo

- En el chat de un agente, una por cada paso que da.
- Con `status="waiting"`, para preguntar antes de un paso delicado como escribir archivos o ejecutar un comando.
- Para un cambio suelto, fuera de una llamada a herramienta, usa la [Vista de diferencias](/pyzed/es/library/diff-view/).

## Uso

```python
import pyzed as pz
from pyzed import ui

class Chat(pz.App):
    def __init__(self):
        self.status = "waiting"

    def answer(self, allowed):
        self.status = "done" if allowed else "rejected"

    def view(self):
        return ui.ToolCall(title="Run", detail="pytest -q", kind="execute", status=self.status,
                           input={"command": "pytest -q"}, output="24 passed",
                           on_allow=lambda e: self.answer(True), on_deny=lambda e: self.answer(False))
```

## Eventos

Llamada a herramienta tiene **3 eventos propios**, en la tabla de abajo. Como todo widget, también tiene los **18 eventos comunes** (`click`, `double_click`, `right_click`, `mouse_enter`, `drag`, `key_down`, `resize`…), que se conectan con `.on(...)`: mira [Eventos](/pyzed/es/guides/events/) y [Eventos de cada componente](/pyzed/es/library/events/).

Es un `pz.Component`, así que también lanza `on_mount` y `on_unmount`, y sus handlers reciben un `pz.Event` cuyo `value` trae el dato.

| Evento | El handler recibe | Cuándo |
| --- | --- | --- |
| `on_allow` | `(event)` | Se pulsó Permitir. |
| `on_allow_always` | `(event)` | Se pulsó Permitir siempre. |
| `on_deny` | `(event)` | Se pulsó Rechazar. |

**El handler recibe** es lo que Pyzed le pasa a tu función: `()` es nada. Cualquier handler también puede ser un mensaje (un valor que no se puede llamar), que va a `update()`.

### Manejar los eventos

Los mismos eventos escritos de tres formas. **Imperativa**: métodos de la app que cambian `self`. **Declarativa**: los handlers producen mensajes y un único `update()` decide. **Funcional**: una función pura dibuja un estado inmutable y pide cambios con `set_state(...)`. Mira [Imperativo, declarativo y funcional](/pyzed/es/guides/code-styles/).

<Tabs syncKey="code-style">
<TabItem label="Imperativo">

```python
class Chat(pz.App):
    def __init__(self):
        self.status = "waiting"

    def answer(self, status):
        self.status = status

    def view(self):                      # a pz.Component: handlers get a pz.Event
        return ui.ToolCall(title="Run", detail="pytest -q", kind="execute", status=self.status,
                           input={"command": "pytest -q"},
                           on_allow=lambda e: self.answer("done"),
                           on_allow_always=lambda e: self.answer("done"),
                           on_deny=lambda e: self.answer("rejected"))
```

</TabItem>
<TabItem label="Declarativo">

```python
class Chat(pz.App):
    status = "waiting"

    def update(self, message):
        match message:
            case "allow":
                self.status = "done"
            case "deny":
                self.status = "rejected"

    def view(self):
        return ui.ToolCall(title="Run", detail="pytest -q", kind="execute", status=self.status,
                           on_allow="allow", on_deny="deny")   # messages work for components too
```

</TabItem>
<TabItem label="Funcional">

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class State:
    status: str = "waiting"


def view(state, set_state):
    return ui.ToolCall(title="Run", detail="pytest -q", kind="execute", status=state.status,
                       on_allow=lambda e: set_state(status="done"),
                       on_deny=lambda e: set_state(status="rejected"))
```

</TabItem>

## Consejos

:::tip
`status` es tuyo: ponlo según lo que diga el agente (`pending`, luego `running`, luego `done` o `failed`; `rejected` tras un Rechazar). `kind` solo elige el icono: `read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch`, `switch_mode` u `other`. La cabecera solo se despliega cuando hay algo que mostrar (`input`, `output`, `images` o `diffs`).
:::

## Propiedades y API

### `ui.ToolCall`

```python
class ToolCall
```

Un componente para una acción de un agente de IA, dibujada como en el panel Agent de Zed: una línea con su icono, lo que hace y dónde (se despliega para mostrar la entrada y la salida), o una tarjeta para las ediciones y los comandos, con el diff o la salida. Mientras `status` es `"waiting"` pregunta en la propia tarjeta: Permitir siempre, Permitir o Rechazar. Mira [Agentes de IA](/pyzed/es/editor/ai-agents/).

| Propiedad | Por defecto | Descripción |
| --- | --- | --- |
| `title` | `""` | Lo que hace ("Editar archivo"). |
| `detail` | `""` | Sobre qué trabaja, en letra monoespaciada. |
| `kind` | `""` | El tipo de ACP: `read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch` u `other` (su icono). |
| `status` | `"done"` | `pending`, `running`, `waiting`, `done`, `failed`, `rejected` o `canceled`. |
| `input` | `None` | Los argumentos (un dict o texto). |
| `output` | `None` | La respuesta (texto o un dict). |
| `images` | `None` | Bytes PNG que se muestran bajo la salida. |
| `diffs` | `None` | Los cambios que hizo: dicts `{"path", "old", "new"}`, que se muestran como diffs de colores (mira `ui.diff_view`). |
| `progress` | `""` | Lo que imprimió hasta ahora (la salida de un comando); sus últimas líneas se ven bajo la cabecera mientras corre. |
| `allow_always` | `True` | Muestra Permitir siempre. |
| `theme` | `None` | Tema. |

Eventos: `on_allow`, `on_allow_always`, `on_deny` ([eventos](#eventos)).
