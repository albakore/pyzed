:::tip[En pocas palabras]
Una lista con buscador de complementos, como una tienda, cada uno con un botón Instalar.
:::

`ui.Catalog` es un componente para cosas que instalar (agentes de un registro, servidores MCP, skills): un buscador sobre una lista con desplazamiento en la que cada fila muestra el nombre, la versión (`version`) y la descripción (`description`), y a la derecha Instalar, Instalado o Actualizar a una versión nueva. `items` son diccionarios u objetos con `id`, `name` y, opcionales, `version`, `description`, `installed` (un bool) y `update` (la versión nueva). Instalar y Actualizar llegan a `on_install` con el id en `event.value`; mientras `busy` tiene un id, esa fila muestra un spinner y los demás botones de Instalar se desactivan. `height` es la altura de la lista.

## Cuándo usarlo

- Para añadir agentes, servidores MCP, skills o plugins desde una lista, dentro de un diálogo o una página de ajustes.

## Uso

```python
import pyzed as pz
from pyzed import ui

class Agents(pz.App):
    def __init__(self):
        self.registry = load_registry()  # [{"id", "name", "version", "description", "installed"}, ...]
        self.installing = ""

    def view(self):
        return ui.Catalog(items=self.registry, busy=self.installing,
                          on_install=lambda e: self.install(e.value))
```

## Eventos

Catálogo tiene **1 evento propios**, en la tabla de abajo. Como todo widget, también tiene los **18 eventos comunes** (`click`, `double_click`, `right_click`, `mouse_enter`, `drag`, `key_down`, `resize`…), que se conectan con `.on(...)`: mira [Eventos](/pyzed/es/guides/events/) y [Eventos de cada componente](/pyzed/es/library/events/).

Es un `pz.Component`, así que también lanza `on_mount` y `on_unmount`, y sus handlers reciben un `pz.Event` cuyo `value` trae el dato.

| Evento | El handler recibe | Cuándo |
| --- | --- | --- |
| `on_install` | `(event)` | Se pulsó Instalar o Actualizar (`event.value` es el id). |

**El handler recibe** es lo que Pyzed le pasa a tu función: `()` es nada. Cualquier handler también puede ser un mensaje (un valor que no se puede llamar), que va a `update()`.

### Manejar los eventos

Los mismos eventos escritos de tres formas. **Imperativa**: métodos de la app que cambian `self`. **Declarativa**: los handlers producen mensajes y un único `update()` decide. **Funcional**: una función pura dibuja un estado inmutable y pide cambios con `set_state(...)`. Mira [Imperativo, declarativo y funcional](/pyzed/es/guides/code-styles/).

<TabItem label="Imperativo">

```python
class Agents(pz.App):
    def __init__(self):
        self.items = [{"id": "goose", "name": "Goose", "version": "1.9.0"},
                      {"id": "codex", "name": "Codex CLI", "version": "0.40.0"}]
        self.installing = ""

    def install(self, ident):            # on_install: event.value is the item's id
        self.installing = ident

    def view(self):
        return ui.Catalog(items=self.items, busy=self.installing, height=200,
                          on_install=lambda e: self.install(e.value))
```

<TabItem label="Declarativo">

```python
from dataclasses import dataclass


@dataclass
class Install:
    ident: str


class Agents(pz.App):
    items = [{"id": "goose", "name": "Goose", "version": "1.9.0"}]
    installing = ""

    def update(self, message):
        match message:
            case Install(ident):
                self.installing = ident

    def view(self):
        return ui.Catalog(items=self.items, busy=self.installing, height=200,
                          on_install=lambda e: Install(e.value))
```

<TabItem label="Funcional">

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class State:
    installed: frozenset = frozenset()


ITEMS = [{"id": "goose", "name": "Goose", "version": "1.9.0"}]


def view(state, set_state):
    items = [{**i, "installed": i["id"] in state.installed} for i in ITEMS]
    return ui.Catalog(items=items, height=200,
                      on_install=lambda e: set_state(installed=state.installed | {e.value}))
```
