SQLAlchemy corre en el mismo proceso que la ventana (la arquitectura 1 de
[Arquitecturas](/pyzed/es/integrations/architectures/)). Hay dos demos:

- **`sqlalchemy_quickstart`**: los modelos `User` y `Address` del
  [ORM Quick Start](https://docs.sqlalchemy.org/en/20/orm/quickstart.html) de SQLAlchemy, con la
  misma ventana sobre una `Session` síncrona o sobre la [extensión asyncio](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html).
- **`sqlalchemy_contacts`**: 20.000 filas en una tabla virtual, con búsqueda y orden en SQL.

## El Quick Start en una ventana

![Usuarios y sus direcciones de email del Quick Start de SQLAlchemy](../../../../assets/integrations/sqlalchemy-quickstart.png)

```bash
cd examples/integrations/sqlalchemy_quickstart
uv run main.py            # Session en hilos de trabajo
uv run main.py --async    # AsyncSession con aiosqlite en el loop de Pyzed
```

<Steps>

1. **Declara los modelos** igual que el Quick Start, con `DeclarativeBase`, `Mapped` y
   `relationship`. La cascada borra las direcciones de un usuario junto con el usuario:

   ```python
   class Base(DeclarativeBase):
       pass

   class User(Base):
       __tablename__ = "user_account"

       id: Mapped[int] = mapped_column(primary_key=True)
       name: Mapped[str] = mapped_column(String(30))
       fullname: Mapped[Optional[str]]
       addresses: Mapped[List["Address"]] = relationship(back_populates="user", cascade="all, delete-orphan")

   class Address(Base):
       __tablename__ = "address"

       id: Mapped[int] = mapped_column(primary_key=True)
       email_address: Mapped[str]
       user_id: Mapped[int] = mapped_column(ForeignKey("user_account.id"))
       user: Mapped["User"] = relationship(back_populates="addresses")
   ```

2. **Crea un Engine y las tablas:**

   ```python
   engine = create_engine("sqlite:///quickstart.db")
   Base.metadata.create_all(engine)
   ```

3. **Abre una Session por unidad de trabajo.** Cada función del backend abre su propia `Session`,
   así que se puede ejecutar sin riesgo en cualquier hilo de trabajo. `selectinload` carga las
   direcciones antes de que se cierre la sesión, para que la ventana pueda leer `user.addresses`
   después:

   ```python
   def users() -> list[User]:
       stmt = select(User).options(selectinload(User.addresses)).order_by(User.name)
       with Session(engine) as session:
           return list(session.scalars(stmt))

   def add_address(user_id: int, email_address: str) -> None:
       with Session(engine) as session:
           user = session.get(User, user_id)
           user.addresses.append(Address(email_address=email_address))
           session.commit()
   ```

4. **Llámalo desde la ventana con `Command.perform`.** La función corre en un hilo y `then`
   recibe el resultado en el hilo de la UI:

   ```python
   def on_start(self):
       return Command.perform(backend.setup, lambda _: self.reload())

   def reload(self):
       return Command.perform(backend.users, self.loaded)

   def add_address(self, *_):
       user_id, email = self.selected_id, self.new_email.strip()
       return Command.perform(lambda: backend.add_address(user_id, email), lambda _: self.reload())
   ```

</Steps>

### La versión asyncio

`async_backend.py` tiene las mismas funciones escritas con `create_async_engine`, un
`async_sessionmaker` y el driver aiosqlite. `Command.perform` ve que son funciones de corrutina y
las ejecuta en el loop de asyncio de Pyzed en lugar de en un hilo, así que `main.py` no cambia:

```python
engine = create_async_engine("sqlite+aiosqlite:///quickstart.db")
async_session = async_sessionmaker(engine, expire_on_commit=False)

async def setup() -> None:
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

async def users() -> list[User]:
    stmt = select(User).options(selectinload(User.addresses)).order_by(User.name)
    async with async_session() as session:
        return list(await session.scalars(stmt))
```

<Aside>
Con `AsyncSession`, la carga perezosa necesitaría un `await`, así que las relaciones se cargan
de antemano con `selectinload`, y `expire_on_commit=False` mantiene los objetos legibles después
de `commit()`. Instala `sqlalchemy[asyncio]` y `aiosqlite`; el extra trae `greenlet`, que la
extensión necesita.
</Aside>

| | `Session` | `AsyncSession` |
| --- | --- | --- |
| Dónde corre | Un hilo de trabajo por llamada | El loop de asyncio de Pyzed |
| Llamada de Pyzed | `Command.perform(función_síncrona, then)` | `Command.perform(función_async, then)` o devolver la corrutina |
| Úsala cuando | La mayoría de las apps de escritorio; cualquier driver | Ya usas drivers de asyncio (asyncpg, aiosqlite) |

## Muchas filas: la demo de contactos

Un gestor de contactos sobre SQLAlchemy 2.0 y SQLite. La tabla tiene 20.000 filas y se desplaza
con fluidez porque `ui.table` solo construye las filas visibles; la búsqueda y el orden se hacen
en SQL, en un hilo de trabajo, así que la ventana nunca espera a la base de datos.

![Una tabla de contactos con 20.000 filas, estadísticas y un panel de edición](../../../../assets/integrations/sqlalchemy.png)

```bash
cd examples/integrations/sqlalchemy_contacts
uv run main.py
```

La demo guarda el código de la base de datos en `db.py`, sin nada de Pyzed, y la ventana en
`main.py`. Vale la pena copiar esa separación: el mismo `db.py` podría servir a una app de
FastAPI o a una CLI.

<Steps>

1. **Los modelos son SQLAlchemy 2.0 normal.**

   ```python
   class Contact(Base):
       __tablename__ = "contacts"

       id: Mapped[int] = mapped_column(primary_key=True)
       name: Mapped[str] = mapped_column(String(80), index=True)
       email: Mapped[str] = mapped_column(String(120), unique=True)
       company: Mapped[str] = mapped_column(String(80), default="")
       city: Mapped[str] = mapped_column(String(60), default="")
   ```

2. **Cada consulta es una función con su propia sesión.** Las sesiones de SQLAlchemy no se
   comparten entre hilos, así que cada función abre una y la cierra. Los objetos cargados
   conservan sus valores después de cerrar la sesión, que es todo lo que necesita la vista:

   ```python
   def search(text, sort, descending):
       column = COLUMNS[sort]
       query = select(Contact).order_by(column.desc() if descending else column, Contact.id)
       if text:
           pattern = f"%{text}%"
           query = query.where(or_(Contact.name.ilike(pattern), Contact.email.ilike(pattern),
                                   Contact.company.ilike(pattern)))
       with Session(engine) as session:
           return list(session.scalars(query))
   ```

3. **Ejecútala con `Command.perform`.** La función corre en un hilo y `then` recibe el resultado
   en el hilo de la UI. Devolver una lista de comandos los ejecuta juntos:

   ```python
   def reload(self):
       query, sort, descending = self.query, self.sort, self.descending
       return [
           Command.perform(lambda: db.search(query, sort, descending), lambda rows: self.loaded(query, rows)),
           Command.perform(db.stats, lambda stats: setattr(self, "stats", stats)),
       ]

   def loaded(self, query, rows):
       if query == self.query:          # a newer search is on its way: keep waiting for it
           self.rows, self.loading = rows, False
   ```

   Copia primero en variables locales el estado que necesitas (`query, sort, ...`): la lambda se
   ejecuta más tarde, en otro hilo, y no debería leer `self` mientras el usuario sigue escribiendo.

4. **Pasa todas las filas a `ui.table`.** Está virtualizada, así que 20.000 filas cuestan lo mismo
   que 20. Al pulsar una cabecera se llama a `on_sort`, que aquí vuelve a ejecutar la consulta con
   un nuevo `ORDER BY`:

   ```python
   ui.table(columns, self.rows, sort_by=self.sort, descending=self.descending, on_sort=self.sort_by,
            on_row_press=self.open, selected=self.editing, striped=True, height="fill")
   ```

5. **Convierte los errores de la base de datos en errores de campo.** `save` devuelve el contacto
   o `{campo: mensaje}`. Una restricción de unicidad se convierte en un mensaje bajo el campo Email:

   ```python
   try:
       session.commit()
   except IntegrityError:
       return {"email": "Another contact already uses this email"}
   ```

   ```python
   ui.field("Email", ui.input(self.draft["email"], ...), error=self.errors.get("email"))
   ```

</Steps>

<Aside type="tip">
¿Prefieres `asyncio`? La `AsyncSession` de SQLAlchemy con `aiosqlite` o `asyncpg` también
funciona: devuelve la corrutina en lugar de usar `Command.perform`. Mira
[Otras librerías](/pyzed/es/integrations/other-libraries/#sqlalchemy-asyncio).
</Aside>
