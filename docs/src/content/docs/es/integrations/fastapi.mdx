La API de esta demo es el tutorial [SQL (Relational) Databases](https://fastapi.tiangolo.com/tutorial/sql-databases/)
de FastAPI, copiado sin cambios: héroes guardados con SQLModel, con modelos separados para crear,
leer y actualizar. La ventana de Pyzed es un cliente de escritorio para ella, y la misma ventana
funciona en las tres [arquitecturas](/pyzed/es/integrations/architectures/) en las que hay una API.

![Una ventana de escritorio con la lista de héroes de la API de FastAPI y un formulario de edición](../../../../assets/integrations/fastapi.png)

```text
fastapi_heroes/
├── main.py            # la API, exactamente como en el tutorial de FastAPI
├── heroes_window.py   # la ventana de Pyzed, que solo habla HTTP (httpx)
├── client.py          # 2. cliente y servidor
├── embedded.py        # 3. servidor integrado
└── in_process.py      # 4. en el proceso
```

## 1. La API, como la enseña FastAPI

<Steps>

1. **Instala FastAPI con sus extras estándar**, que traen la CLI `fastapi` y Uvicorn. El
   `pyproject.toml` de la demo ya los incluye:

   <Commands
   	uv={`
   		cd examples/integrations/fastapi_heroes
   		uv add "fastapi[standard]" sqlmodel httpx   # en tu propio proyecto
   	`}
   	pip={`
   		cd examples/integrations/fastapi_heroes
   		{venv}
   		{activate}
   		pip install pyzed-ui "fastapi[standard]" sqlmodel httpx
   	`}
   	python={`
   		cd examples/integrations/fastapi_heroes
   		{py} -m pip install pyzed-ui "fastapi[standard]" sqlmodel httpx
   	`}
   />

2. **Escribe los modelos.** `HeroBase` tiene los campos comunes, `Hero` es la tabla, `HeroPublic`
   es lo que devuelve la API (nunca el `secret_name`), y `HeroCreate` y `HeroUpdate` describen
   los cuerpos de las peticiones:

   ```python
   class HeroBase(SQLModel):
       name: str = Field(index=True)
       age: int | None = Field(default=None, index=True)

   class Hero(HeroBase, table=True):
       id: int | None = Field(default=None, primary_key=True)
       secret_name: str

   class HeroPublic(HeroBase):
       id: int

   class HeroCreate(HeroBase):
       secret_name: str

   class HeroUpdate(HeroBase):
       name: str | None = None
       age: int | None = None
       secret_name: str | None = None
   ```

3. **Declara una dependencia de sesión** para que cada petición tenga su propia `Session`:

   ```python
   def get_session():
       with Session(engine) as session:
           yield session

   SessionDep = Annotated[Session, Depends(get_session)]
   ```

4. **Escribe las operaciones de ruta.** `response_model` filtra la salida y FastAPI valida la
   entrada, y responde **422** con una entrada por cada campo inválido:

   ```python
   @app.post("/heroes/", response_model=HeroPublic)
   def create_hero(hero: HeroCreate, session: SessionDep):
       db_hero = Hero.model_validate(hero)
       session.add(db_hero)
       session.commit()
       session.refresh(db_hero)
       return db_hero

   @app.patch("/heroes/{hero_id}", response_model=HeroPublic)
   def update_hero(hero_id: int, hero: HeroUpdate, session: SessionDep):
       hero_db = session.get(Hero, hero_id)
       if not hero_db:
           raise HTTPException(status_code=404, detail="Hero not found")
       hero_data = hero.model_dump(exclude_unset=True)
       hero_db.sqlmodel_update(hero_data)
       ...
   ```

5. **Ejecútala con la CLI de FastAPI** y abre la documentación interactiva en
   [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs):

   <Commands
   	uv={`uv run fastapi dev main.py`}
   	pip={`fastapi dev main.py`}
   	python={`{py} -m fastapi dev main.py`}
   />

   `fastapi dev` recarga con cada cambio; `fastapi run main.py` es el comando de producción.

</Steps>

## El cliente de escritorio

`heroes_window.py` es una `pz.App` que habla con la API con un `httpx.AsyncClient`. Recibe una
función que crea el cliente, así que la misma ventana funciona con cualquiera de las
arquitecturas de abajo.

<Steps>

1. **Envía las peticiones desde corrutinas.** Devolver una corrutina desde un callback la ejecuta
   en el loop de asyncio de Pyzed, y lo que devuelve llega a `update`. El cliente se crea la
   primera vez que se usa, para que pertenezca a ese loop:

   ```python
   async def api(self, method, url, **kwargs):
       if self.client is None:
           self.client = self.make_client()
       try:
           return await self.client.request(method, url, **kwargs)
       except httpx.HTTPError as error:
           return f"Can't reach the API: {error}"

   async def load(self):
       response = await self.api("GET", "/heroes/", params={"limit": 100})
       if isinstance(response, str):
           return ("offline", response)
       return ("loaded", response.json())
   ```

2. **Crea con POST y edita con PATCH.** Solo se envían los campos que el usuario rellenó, que es
   lo que esperan `HeroUpdate` y `exclude_unset=True`:

   ```python
   async def save(self):
       body = {key: value for key, value in self.draft.items() if value != ""}
       if self.selected is None:
           response = await self.api("POST", "/heroes/", json=body)
       else:
           response = await self.api("PATCH", f"/heroes/{self.selected['id']}", json=body)
       if response.status_code == 422:
           return ("invalid", response.json())
       ...
   ```

3. **Muestra el 422 de FastAPI en cada campo.** `pz.validation_errors` lee `{"detail": [...]}` y
   devuelve `{"age": "Input should be a valid integer, ..."}`:

   ```python
   def update(self, message):
       kind, value = message
       if kind == "invalid":
           self.errors = pz.validation_errors(value)
   ```

</Steps>

## 4. En el proceso

Sin servidor y sin puerto: `httpx.ASGITransport` entrega cada petición a la app de FastAPI como
una llamada a función. El programa funciona sin conexión, y el código de la API no cambia.

<Commands
	uv={`uv run in_process.py`}
	pip={`python in_process.py`}
	python={`{py} in_process.py`}
/>

<Code code={inProcess} lang="py" title="in_process.py" />

<Aside type="caution">
`ASGITransport` no envía los eventos de startup ni de lifespan, así que el código de
`@app.on_event("startup")` o de una función `lifespan` no se ejecuta. `in_process.py` llama a
`create_db_and_tables()` por su cuenta.
</Aside>
