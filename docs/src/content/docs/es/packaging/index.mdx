Cuando tu app funciona en tu equipo, `pyzed build` la empaqueta: Python, Pyzed, tus dependencias, tu código y tus
formularios van a una carpeta (o un solo archivo) que funciona por sí sola. Ejecútalo desde la raíz de tu
[proyecto](/pyzed/es/getting-started/new-project/):

<Tabs syncKey="pkg">
	<TabItem label="uv">
		```bash title="Windows, macOS y Linux"
		uv run pyzed build
		```
	</TabItem>
	<TabItem label="pip">
		```bash title="macOS y Linux"
		source .venv/bin/activate
		pyzed build          # o: python -m pyzed build
		```

		```powershell title="Windows (PowerShell)"
		.venv\Scripts\activate
		pyzed build          # o: python -m pyzed build
		```
	</TabItem>
</Tabs>

| Compilas en | Obtienes | La gente la ejecuta |
| --- | --- | --- |
| Windows | `dist\Shop\Shop.exe` | Con doble clic, o desde un zip o un instalador |
| macOS | `dist/Shop.app` | Abriéndola (fírmala y notarízala para compartirla) |
| Linux | `dist/Shop/Shop` | Con `./Shop`, o como AppImage, .deb o Flatpak |

<Aside type="caution" title="Una compilación por plataforma">
Una compilación solo funciona en el sistema donde se hizo: compila la app de Windows en Windows, la de macOS en
macOS y la de Linux en Linux. Un flujo de CI puede hacer las tres por ti.
</Aside>

<Aside type="note">
`pyzed build` ejecuta [PyInstaller](https://pyinstaller.org) dentro del entorno de tu proyecto mediante
[uv](https://docs.astral.sh/uv/), así que uv tiene que estar instalado aunque uses pip para todo lo demás.
</Aside>
