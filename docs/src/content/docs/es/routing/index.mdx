El sistema de rutas de Pyzed permite hacer una app con muchas pantallas igual que el App Router
de Next.js hace una web: **cada carpeta de `app/` es una parte de la dirección**, y unos pocos
archivos con nombres fijos dicen qué muestra cada dirección. Si conoces Next.js, ya sabes usarlo;
si no, se aprende en diez minutos, y las mismas carpetas siguen sirviendo cuando la app llega a
cincuenta pantallas.

```text
app/
├── layout.py               envuelve todas las páginas (una barra lateral, una cabecera) y guarda su estado
├── page.py                 /
├── loading.py              se muestra mientras una página carga sus datos
├── error.py                se muestra cuando algo falla, con «Reintentar»
├── not_found.py            direcciones que no existen
├── middleware.py           corre antes de cada navegación (comprobar la sesión)
├── products/
│   ├── page.py             /products
│   └── [id]/page.py        /products/3      params["id"] == "3"
└── settings/
    ├── layout.py           pestañas alrededor de las páginas de ajustes
    └── profile/page.py     /settings/profile
```

<Aside type="note" title="En palabras sencillas">
Una *dirección* es dónde estás dentro de la app, como la URL de una web: `/products/3` es el
producto número 3. Ir a otra dirección es *navegar*. Una *página* es lo que muestra una
dirección, y un *layout* es el marco alrededor de las páginas (una barra lateral, un menú) que
se queda quieto mientras te mueves.
</Aside>

## Empieza en un minuto

<Steps>

1. Crea un proyecto con la plantilla de rutas:

   ```bash
   pyzed new shop --router            # un proyecto de uv
   pyzed new shop --script --router   # o solo main.py y app/, sin uv
   ```

2. Ejecútalo con recarga en caliente: lo que guardas aparece al instante y las carpetas nuevas
   se vuelven páginas nuevas.

   ```bash
   cd shop
   uv run pyzed dev main.py           # o: python main.py
   ```

3. Añade páginas desde la línea de comandos, o creando tú las carpetas:

   ```bash
   pyzed route add /orders/[id] --load --loading
   pyzed route list
   ```

</Steps>

`main.py` solo arranca el router; todo lo demás vive en `app/`:

```python
import pyzed as pz


class Shop(pz.RouterApp):
    routes = "app"        # la carpeta, junto a este archivo
    title = "Shop"        # el título de la ventana cuando una página no tiene
    size = (1000, 680)


if __name__ == "__main__":
    pz.run(Shop)
```

## Qué incluye

- **Las carpetas son direcciones**: partes fijas, `[id]`, `[...slug]` y `[[...slug]]`, `(grupos)`
  que solo organizan y carpetas `_privadas` para el código de apoyo.
- **Layouts que guardan su estado** (una barra lateral plegada sigue plegada) y **templates** que
  empiezan de cero en cada navegación.
- **Datos fuera del hilo de la interfaz**: `async def load(params)` junto a la página; mientras
  tanto se ve el `loading.py` más cercano, y los datos se guardan en caché y se refrescan como en
  Next.js.
- **Acciones** para los cambios (`@pz.action`): `pending`, `result` y `error` para el botón, y los
  datos de la página se recargan al terminar.
- **Estado global** (`pz.Store`): el carrito, la sesión, las preferencias, que cualquier página
  lee; solo se vuelve a dibujar lo que lo leyó.
- **Middleware** (`middleware.py`): redirecciones, reescrituras y comprobaciones antes de mostrar
  una página.
- **Notificaciones nativas** (`pz.notify`) cuyo clic abre una página de la app.
- **Historial**: atrás y adelante con Alt+Izquierda/Derecha, los botones laterales del ratón y el
  botón atrás de Android, y el título de la ventana sigue a la página.
- **Las direcciones son URLs**, así que la misma carpeta `app/` corresponde a la barra de
  direcciones de un navegador cuando la app pase a la web.
