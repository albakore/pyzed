The API in this demo is FastAPI's own [SQL (Relational) Databases](https://fastapi.tiangolo.com/tutorial/sql-databases/)
tutorial, copied without changes: heroes stored with SQLModel, with separate models for creating,
reading and updating. The Pyzed window is a desktop client for it, and the same window runs in
the three [architectures](/pyzed/integrations/architectures/) that involve an API.

![A desktop window listing heroes from the FastAPI API, with an edit form](../../../assets/integrations/fastapi.png)

```text
fastapi_heroes/
├── main.py            # the API, exactly as in FastAPI's tutorial
├── heroes_window.py   # the Pyzed window, which only speaks HTTP (httpx)
├── client.py          # 2. client and server
├── embedded.py        # 3. embedded server
└── in_process.py      # 4. in process
```

## 1. The API, as FastAPI teaches it

<Steps>

1. **Install FastAPI with its standard extras**, which bring the `fastapi` CLI and Uvicorn. The
   demo's `pyproject.toml` already lists them:

   <Commands
   	uv={`
   		cd examples/integrations/fastapi_heroes
   		uv add "fastapi[standard]" sqlmodel httpx   # in your own project
   	`}
   	pip={`
   		cd examples/integrations/fastapi_heroes
   		{venv}
   		{activate}
   		pip install pyzed-ui "fastapi[standard]" sqlmodel httpx
   	`}
   	python={`
   		cd examples/integrations/fastapi_heroes
   		{py} -m pip install pyzed-ui "fastapi[standard]" sqlmodel httpx
   	`}
   />

2. **Write the models.** `HeroBase` holds the shared fields, `Hero` is the table, `HeroPublic`
   is what the API returns (never the `secret_name`), and `HeroCreate` and `HeroUpdate` describe
   the request bodies:

   ```python
   class HeroBase(SQLModel):
       name: str = Field(index=True)
       age: int | None = Field(default=None, index=True)

   class Hero(HeroBase, table=True):
       id: int | None = Field(default=None, primary_key=True)
       secret_name: str

   class HeroPublic(HeroBase):
       id: int

   class HeroCreate(HeroBase):
       secret_name: str

   class HeroUpdate(HeroBase):
       name: str | None = None
       age: int | None = None
       secret_name: str | None = None
   ```

3. **Declare a session dependency** so every request gets its own `Session`:

   ```python
   def get_session():
       with Session(engine) as session:
           yield session

   SessionDep = Annotated[Session, Depends(get_session)]
   ```

4. **Write the path operations.** `response_model` filters the output and FastAPI validates the
   input, returning **422** with one entry per invalid field:

   ```python
   @app.post("/heroes/", response_model=HeroPublic)
   def create_hero(hero: HeroCreate, session: SessionDep):
       db_hero = Hero.model_validate(hero)
       session.add(db_hero)
       session.commit()
       session.refresh(db_hero)
       return db_hero

   @app.patch("/heroes/{hero_id}", response_model=HeroPublic)
   def update_hero(hero_id: int, hero: HeroUpdate, session: SessionDep):
       hero_db = session.get(Hero, hero_id)
       if not hero_db:
           raise HTTPException(status_code=404, detail="Hero not found")
       hero_data = hero.model_dump(exclude_unset=True)
       hero_db.sqlmodel_update(hero_data)
       ...
   ```

5. **Run it with the FastAPI CLI** and open the interactive docs at
   [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs):

   <Commands
   	uv={`uv run fastapi dev main.py`}
   	pip={`fastapi dev main.py`}
   	python={`{py} -m fastapi dev main.py`}
   />

   `fastapi dev` reloads on every change; `fastapi run main.py` is the production command.

</Steps>

## The desktop client

`heroes_window.py` is a `pz.App` that talks to the API with an `httpx.AsyncClient`. It receives a
function that creates the client, so the same window works with any of the architectures below.

<Steps>

1. **Send requests from coroutines.** Returning a coroutine from a callback runs it on Pyzed's
   asyncio loop; its return value reaches `update`. The client is created on first use, so it
   belongs to that loop:

   ```python
   async def api(self, method, url, **kwargs):
       if self.client is None:
           self.client = self.make_client()
       try:
           return await self.client.request(method, url, **kwargs)
       except httpx.HTTPError as error:
           return f"Can't reach the API: {error}"

   async def load(self):
       response = await self.api("GET", "/heroes/", params={"limit": 100})
       if isinstance(response, str):
           return ("offline", response)
       return ("loaded", response.json())
   ```

2. **Create with POST and edit with PATCH.** Only the fields the user filled in are sent, which is
   what `HeroUpdate` and `exclude_unset=True` expect:

   ```python
   async def save(self):
       body = {key: value for key, value in self.draft.items() if value != ""}
       if self.selected is None:
           response = await self.api("POST", "/heroes/", json=body)
       else:
           response = await self.api("PATCH", f"/heroes/{self.selected['id']}", json=body)
       if response.status_code == 422:
           return ("invalid", response.json())
       ...
   ```

3. **Show FastAPI's 422 on each field.** `pz.validation_errors` reads `{"detail": [...]}` and
   returns `{"age": "Input should be a valid integer, ..."}`:

   ```python
   def update(self, message):
       kind, value = message
       if kind == "invalid":
           self.errors = pz.validation_errors(value)
   ```

</Steps>

## 4. In process

No server and no port: `httpx.ASGITransport` hands each request to the FastAPI app as a function
call. The program works offline, and the API code stays the same.

<Commands
	uv={`uv run in_process.py`}
	pip={`python in_process.py`}
	python={`{py} in_process.py`}
/>

<Code code={inProcess} lang="py" title="in_process.py" />

<Aside type="caution">
`ASGITransport` doesn't send startup or lifespan events, so code in `@app.on_event("startup")`
or a `lifespan` function doesn't run. `in_process.py` calls `create_db_and_tables()` itself.
</Aside>
