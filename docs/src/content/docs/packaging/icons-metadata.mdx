An app's identity is a few small things: its **name**, its **icon**, its **version** and, on macOS, its **bundle
identifier**. Some are set in `pyproject.toml` for `pyzed build`, some in your app.

## Name and version

| What | Where | Example |
| --- | --- | --- |
| Executable and bundle name | `[tool.pyzed.build] name` (or `--name`) | `name = "Shop"` → `Shop.exe`, `Shop.app` |
| Window title | The form's **Title** in the designer, or `title` of your `pz.App` | `title = "Shop"` |
| Version | `[project] version` in `pyproject.toml` | `version = "1.2.0"` |

`pyzed build` does not write the version into the executable's metadata. If your app shows its version or
[checks for updates](/pyzed/packaging/updates/), keep it in your code, for example in your package's `__init__.py`,
and update it together with `pyproject.toml`:

```python title="src/shop/__init__.py"
__version__ = "1.2.0"
```

<Aside type="note" title="Why not importlib.metadata?">
`importlib.metadata.version("shop")` reads the installed package's metadata, which PyInstaller does not copy into the
bundle unless you ask it to (`args = ["--copy-metadata", "shop"]`). A constant in your code always works.
</Aside>

## The icon

Each system wants its own format:

| System | Format | Sizes inside the file | Setting |
| --- | --- | --- | --- |
| Windows | `.ico` | 16, 24, 32, 48, 64, 128, 256 px | `icon = "assets/icon.ico"` |
| macOS | `.icns` | 16 to 1024 px | `icon = "assets/icon.icns"` |
| Linux | `.png` (512 px is enough) | - | In the `.desktop` file (see [Linux](/pyzed/packaging/linux/#add-it-to-the-application-menu)) |

`icon` in `[tool.pyzed.build]` is a single path. When you build on several systems, the easiest setup is **one PNG
for all of them**: PyInstaller converts a PNG to `.ico` or `.icns` when [Pillow](https://pypi.org/project/pillow/) is
installed in the build environment, and `pyzed build` runs PyInstaller in your project's environment:

<Tabs syncKey="pkg">
	<TabItem label="uv">
		```bash
		uv add --dev pillow      # or: pyzed add --dev pillow
		```
	</TabItem>
	<TabItem label="pip">
		```bash
		pyzed add --dev pillow   # pyzed build needs uv anyway; this adds Pillow with it
		```
	</TabItem>
</Tabs>

```toml title="pyproject.toml"
[tool.pyzed.build]
icon = "assets/icon.png"   # 1024 x 1024; converted on Windows and macOS
```

For the sharpest result at small sizes, make the `.ico` and `.icns` files yourself (below) and set `icon` to the one
for the system you build on.

### Making the icon files yourself

Start from a square PNG of 1024 × 1024 pixels.

<Tabs>
	<TabItem label="Windows .ico (Python)">
		```python
		from PIL import Image  # pip install pillow

		Image.open("icon.png").save("icon.ico", sizes=[(s, s) for s in (16, 24, 32, 48, 64, 128, 256)])
		```
	</TabItem>
	<TabItem label="macOS .icns">
		```bash
		mkdir icon.iconset
		for s in 16 32 128 256 512; do
		  sips -z $s $s icon.png --out icon.iconset/icon_${s}x${s}.png
		  sips -z $((s*2)) $((s*2)) icon.png --out icon.iconset/icon_${s}x${s}@2x.png
		done
		iconutil -c icns icon.iconset   # writes icon.icns (macOS only)
		```
	</TabItem>
	<TabItem label="Linux .png">
		```bash
		# ImageMagick
		convert icon.png -resize 512x512 icon-512.png
		```
	</TabItem>
</Tabs>

## The icon of the window

The icon above is the one of the **file** (in Explorer, Finder, the Dock and the taskbar).

<Aside type="caution" title="Not supported yet">
Setting a separate icon for the window itself (the small icon some systems draw in the title bar) from Python is not
supported yet.
</Aside>

## macOS bundle identifier

```toml title="pyproject.toml"
[tool.pyzed.build]
args = ["--osx-bundle-identifier", "com.acme.shop"]
```

Use a reverse domain you own. macOS keeps the app's preferences and privacy permissions under it, so do not change it
between releases.

## Windows file properties

The **Details** tab of an `.exe`'s properties (company, product name, version) comes from a version resource.
PyInstaller can add one from a version file:

```toml title="pyproject.toml"
[tool.pyzed.build]
args = ["--version-file", "assets/version.txt"]
```

Write `version.txt` by hand (see PyInstaller's
[version file format](https://pyinstaller.org/en/stable/usage.html#capturing-windows-version-data)) or capture one
from an existing `.exe` with `pyi-grab_version`. Paths in `args` reach PyInstaller unchanged, and PyInstaller writes
its spec file to `build/pyzed/`: if it cannot find the file, give its absolute path.

<Aside type="caution" title="Not generated by pyzed build yet">
Pyzed does not generate the version file or the macOS `Info.plist` entries for you; both go through `args`.
</Aside>
