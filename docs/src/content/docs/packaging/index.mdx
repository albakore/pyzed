When your app works on your machine, `pyzed build` packages it: Python, Pyzed, your dependencies, your code and
your forms go into one folder (or one file) that runs on its own. Run it from the root of your
[project](/pyzed/getting-started/new-project/):

<Tabs syncKey="pkg">
	<TabItem label="uv">
		```bash title="Windows, macOS and Linux"
		uv run pyzed build
		```
	</TabItem>
	<TabItem label="pip">
		```bash title="macOS and Linux"
		source .venv/bin/activate
		pyzed build          # or: python -m pyzed build
		```

		```powershell title="Windows (PowerShell)"
		.venv\Scripts\activate
		pyzed build          # or: python -m pyzed build
		```
	</TabItem>
</Tabs>

| You build on | You get | People run it by |
| --- | --- | --- |
| Windows | `dist\Shop\Shop.exe` | Double-clicking it, or from a zip or an installer |
| macOS | `dist/Shop.app` | Opening it (sign and notarize it to share it) |
| Linux | `dist/Shop/Shop` | `./Shop`, or as an AppImage, .deb or Flatpak |

<Aside type="caution" title="One build per platform">
A build only runs on the system it was made on: build the Windows app on Windows, the macOS app on macOS and the
Linux app on Linux. A CI workflow can do all three for you.
</Aside>

<Aside type="note">
`pyzed build` runs [PyInstaller](https://pyinstaller.org) inside your project's environment through
[uv](https://docs.astral.sh/uv/), so uv must be installed even if you use pip for everything else.
</Aside>
