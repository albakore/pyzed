Pyzed requires **Python 3.10 or later**.

## From PyPI

<Commands
	uv={`
		uv add pyzed-ui          # in a uv project
		uv run python main.py
	`}
	pip={`
		{venv}       # once per project
		{activate}
		pip install pyzed-ui
		python main.py
	`}
	python={`
		{py} -m pip install pyzed-ui
		{py} main.py
	`}
/>

- **uv** manages a project for you: [Create a project](/pyzed/getting-started/new-project/) starts a new app this
  way, and it is what the rest of these docs use. Install it from [docs.astral.sh/uv](https://docs.astral.sh/uv/).
- **pip** installs into a *virtual environment* (`.venv`), a folder that keeps this project's packages apart from
  the rest of your computer. Activate it in each new terminal before running your app.
- **python** installs into the Python on your computer, with nothing else to learn. On Windows, `py` is the Python
  launcher that comes with the installer from [python.org](https://www.python.org/downloads/); on macOS and Linux
  the command is usually `python3`.

The package is called `pyzed-ui` on PyPI (the name `pyzed` was already taken), but it is imported as `pyzed`.
The prebuilt wheels for Linux, macOS and Windows include the Rust engine, so you don't
need to compile anything.

<Aside type="note" title="Only prebuilt wheels">
PyPI only has wheels, built and tested by the release pipeline for Linux (x86_64 and ARM, glibc and musl),
macOS (Intel and Apple Silicon) and Windows (x64 and ARM). One wheel covers every Python from 3.10. On any
other platform the install stops with an error instead of compiling; install from source (below) there.
</Aside>

## From source

<Commands
	uv={`uv add git+https://github.com/albakore/pyzed`}
	pip={`pip install git+https://github.com/albakore/pyzed     # with .venv active`}
	python={`{py} -m pip install git+https://github.com/albakore/pyzed`}
/>

This compiles the Rust extension, so you need [Rust 1.88 or newer](https://rustup.rs) (`rustup update` upgrades an older one) and your
platform's system dependencies:

<Tabs syncKey="os">
	<TabItem label="Linux">
		```bash
		# Debian / Ubuntu
		sudo apt install build-essential libxkbcommon-x11-0
		curl https://sh.rustup.rs -sSf | sh
		```
	</TabItem>
	<TabItem label="macOS">
		```bash
		xcode-select --install
		curl https://sh.rustup.rs -sSf | sh
		```
	</TabItem>
	<TabItem label="Windows">
		Install [Rust with rustup](https://rustup.rs) and the *Build Tools for Visual Studio*
		("Desktop development with C++" workload).
	</TabItem>
</Tabs>

## Developing Pyzed

To work on Pyzed itself, clone the repository. You need [Rust 1.88 or newer](https://rustup.rs) (`rustup update` upgrades an older one) and the
system dependencies above.

<Commands
	uv={`
		git clone https://github.com/albakore/pyzed
		cd pyzed
		uv sync                          # creates .venv, builds the Rust core (release) and installs pyzed editable
		uv run pytest tests
		uv run python examples/gallery.py
	`}
	pip={`
		git clone https://github.com/albakore/pyzed
		cd pyzed
		{venv}
		{activate}
		pip install maturin pytest
		maturin develop --release        # run it again after changing Rust code
		pytest tests
		python examples/gallery.py
	`}
/>

- `uv sync` also installs the `test` group (maturin and pytest). The first build takes a few minutes.
- Python changes under `python/pyzed/` are picked up directly.
- With uv, the next `uv run` or `uv sync` after changing Rust code (`src/`) rebuilds the core by itself; with pip,
  run `maturin develop --release` again. Use `--release`: the debug build is much slower when using the window.
- `uv sync --extra designer` adds ty and ruff for the designer's code editor.
- On Linux a build from source plays no sound by default, so it builds without extra system packages:
  `pyzed.audio` renders offline and on its silent clock. For audio devices and MIDI, install ALSA's headers
  (`sudo apt install libasound2-dev pkg-config`; Fedora: `sudo dnf install alsa-lib-devel`) and build with
  `maturin develop --release --features alsa` (with uv, keep `MATURIN_PEP517_ARGS="--features alsa"` exported and run `uv sync --reinstall-package pyzed-ui`).

## Linux and WSL

Pyzed sets a few defaults before the first window opens:

- **GPU driver warnings are silenced.** Mesa prints messages such as `libEGL warning: failed to
  get driver name for fd -1` or `MESA: error: ZINK: failed to choose pdev` while the renderer
  looks for a working backend. They are harmless, so Pyzed sets `EGL_LOG_LEVEL=fatal` and
  `MESA_LOG=null`. Set `PYZED_GPU_LOGS=1` to see them again.
- **WSL uses X11.** The Wayland compositor of WSLg drops the connection when a window is
  maximized or resized, which prints `Io error: Broken pipe (os error 32)`. Under WSL, Pyzed
  uses X11 (through XWayland) instead. Set `PYZED_WAYLAND=1` to keep Wayland.
- **WSL opens pages in Windows' browser.** WSL usually has no browser of its own, so sign-ins (the
  AI agents'), the docs and other links open in your default Windows browser. Pages that call
  back to Pyzed on `127.0.0.1` still reach it through WSL's localhost forwarding. Programs that
  need a terminal, such as the Claude Code sign-in, open in Windows Terminal (or a console) back
  in your WSL distribution. Set `BROWSER` to pick a browser yourself.

Variables you set yourself (`EGL_LOG_LEVEL`, `MESA_LOG`, `WAYLAND_DISPLAY`, `BROWSER`...) are never changed.

## Verify the installation

<Commands
	uv={`
		uv run python -c "import pyzed; print(pyzed.__version__)"
		uv run pyzed icons folder
	`}
	pip={`
		python -c "import pyzed; print(pyzed.__version__)"
		pyzed icons folder
	`}
	python={`
		{py} -c "import pyzed; print(pyzed.__version__)"
		{py} -m pyzed icons folder
	`}
/>

The first line prints the version; the second lists the icon names that contain "folder".
