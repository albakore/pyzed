A UI must never block waiting on the network or the disk. Pyzed offers two tools:

- **`Command.perform(fn, then)`** runs a blocking function on another thread and hands you the
  result.
- **`pz.post(message)`** sends messages to the app from any thread (progress, events).

| Goal | Time | Level | You need |
| --- | --- | --- | --- |
| Downloads with progress bars and notifications that never freeze the window | 30 minutes | Intermediate · Python | [Dialogs and notifications](/pyzed/tutorials/intermediate/dialogs-feedback/) |

## What you'll learn

- Why slow work must leave the UI thread, and the two ways to move it out.
- Get one result back with `Command.perform`.
- Report progress from a thread with `pz.post` and handle it in `update`.
- Show notifications that dismiss themselves.

<Aside type="tip">
If you prefer `asyncio`, `update` and callbacks can also be `async def` functions or `async`
generators, and `pz.listen` turns a stream into a subscription. See the
[Async and subscriptions](/pyzed/guides/async/) guide.
</Aside>

<Steps>

1. **One result: `Command.perform`.** For "do this and tell me when it's done":

   ```python
   def check_updates(self):
       self.checking = True
       return Command.perform(self.fetch_latest_version, self.got_version)

   @staticmethod
   def fetch_latest_version():
       time.sleep(1.5)          # e.g. an HTTP request
       return "0.2.0"

   def got_version(self, version):     # runs on the UI thread
       self.checking, self.latest = False, version
   ```

   While `self.checking` is `True`, the button is drawn disabled (`on_press=None`).

2. **Many results: `pz.post`.** A thread of your own reports progress with messages that reach
   `update`:

   ```python
   def start(self, name):
       self.progress[name] = 0.0

       def worker():
           done = 0.0
           while done < 1.0:
               time.sleep(0.05)
               done = min(1.0, done + 0.05)
               pz.post(("progress", name, done))
           pz.post(("finished", name))

       threading.Thread(target=worker, daemon=True).start()

   def update(self, message):
       kind, name, *rest = message
       if kind == "progress":
           self.progress[name] = rest[0]
       elif kind == "finished":
           self.notify(f"{name} downloaded", kind="success")
   ```

3. **Self-dismissing notifications.** A `threading.Timer` posts the dismiss message:

   ```python
   def notify(self, title, message=None, kind="info"):
       toast_id = f"{time.monotonic()}"
       self.toasts.append((toast_id, title, message, kind))
       threading.Timer(4, pz.post, args=(("dismiss", toast_id),)).start()

   # in view():
   return ui.toasts(body, [ui.toast(t, m, kind=k, on_dismiss=("dismiss", i)) for i, t, m, k in self.toasts])
   ```

</Steps>

<Aside>
State is only modified on the UI thread (in `update` and in callbacks). Worker threads don't
touch `self`: they send messages with `pz.post`.
</Aside>

## Events in this tutorial

This app is **declarative**: the events of the threads are messages. `pz.post(("progress", name, done))` from a
worker thread and `on_dismiss=("dismiss", tid)` of each toast both reach `update(message)`, which unpacks the tuple.

| Source | Event | Message or handler |
| --- | --- | --- |
| **Download** button | `on_press` | `lambda: self.start(name)` |
| The worker thread | progress, finished | `pz.post(("progress", name, done))`, `pz.post(("finished", name))` |
| **Check for updates** | `on_press` | `self.check_updates`, which returns `Command.perform(work, done)` |
| `Command.perform` | the work finished | `self.got_version(result)` |
| A toast | `on_dismiss` | the message `("dismiss", tid)` |

### Try more events

```python
def row(self, name):
    ...
    return pz.column([...]).on(double_click=lambda: self.start(name))   # double click: download again

def subscriptions(self):                    # an event every second while something downloads
    busy = any(v < 1 for v in self.progress.values())
    return [pz.every(1, ("tick", "", None))] if busy else []
```

`update` gets `("tick", "", None)` every second while a download runs, and nothing once they finish: a subscription
you stop returning stops.
