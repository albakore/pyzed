Forms are where most desktop apps start: fields, buttons, rules and messages. Pyzed gives you two ways to make
them, and you can mix both in one app:

- **Draw them** in [Pyzed Design](/pyzed/editor/), the visual designer: drag controls onto a window, set their
  properties, and write only the Python that runs when something happens (a `.pzform` file plus a `.py` file with
  the handlers). If you have used Visual Basic, Qt Designer or the editors of Godot and Unreal Engine, it will feel
  familiar.
- **Write them** in Python with the [components library](/pyzed/library/): `ui.field`, `ui.input`, `ui.select`,
  `ui.switch`... in a `view()` method.

<Aside type="tip" title="Open a form in the designer">
Every `.pzform` on this page opens in Pyzed Design: `pyzed design path/to/form.pzform`. Press <kbd>F5</kbd> there
to run it, and look at the **Events** panel to see which handler each control calls.
</Aside>

## Sign-in form

Drawn in the designer: an email and a password, a "remember me" check box, and a button that shows a progress bar
while it "signs in". The Python file is just four small functions, one per event.

<Media src={loginRun} alt="A sign-in form running: email, password, remember me and a Sign in button" size="narrow" />

- Controls are attributes of `form`: `form.email.text`, `form.status.color = "error"`, `form.progress.show()`.
- A **Timer** control (`ticker`) calls `ticker_tick` every few milliseconds while it runs; that is how the
  progress bar fills up without blocking the window.

## Sign-up with validation

Every field is **bound** to `form.data` and has **rules** set in the Properties panel (required, an email, at least
8 characters, the same as another field). One line, `form.validate()`, checks them all and shows the messages
next to the fields; the greeting and the summary update by themselves as you type.

## Sign-up validated by Pydantic

The rules of this form live in a [Pydantic](https://docs.pydantic.dev) model, the same kind of model a web API
would use. The window keeps what the user types as plain text and hands it to `SignUp.model_validate`; Pydantic
converts the values (a date, an email, a yes/no), checks every rule, and `pz.validation_errors` turns its errors
into a message per field. Accounts are saved to `accounts.json`.

{/* media: showcase/pydantic_signup */}
